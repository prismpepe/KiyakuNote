# 簡易仕様書

規約ノート（KiyakuNote）のデータ形式と動作の仕様です。

## 1. 考え方

- **正本は Markdown + git。** 履歴・差分・復元が標準で使え、人が読んで確かめられます。
- **条番号を識別子にしない。** 番号は改正のたびに変わります。各条・項・号に**不変の ID** を付け、参照は ID で書き、
  番号は出力のときに計算します。「前条」「次項」や「第5条の2」を文中に直書きして正規表現で直す方式は採りません。
- 検索用の SQLite は、正本から作る**使い捨ての派生物**です（壊れたら作り直します）。
- **版は「総会決議日・施行日」の単位**で、git のコミットとは別に持ちます。

```
Markdown（正本・git）──ビルド──▶ 出力（Markdown / Word、新旧対照表）
                      └──▶ SQLite（検索）
```

## 2. プロジェクトのフォルダ

```
src/
  kiyaku.md           規約の本体（文書ID: kiyaku）
  bylaw-parking.md    細則（文書ごとに1ファイル）
  tbl-1.md            別表
  app-1.md            別紙
  revisions.yaml      版（改正）の一覧
```

`src/` の `*.md`（先頭が `---` の front matter で始まるもの）が文書です。1ファイル＝1文書。

## 3. 文書（front matter）

```yaml
---
doc: kiyaku            # 文書ID（必須。全体で一意）
kind: 規約             # 規約 | 使用細則 | 細則 | 別表 | 別紙 | 別図
title: サンプルハイツ管理規約
short: 規約            # 他の文書から参照されるときの呼び名
numbering: renumber    # 条番号の既定（見出しに branch を付けた条だけ枝番になる）
parent: kiyaku         # 細則・別表などが属する文書（任意）
appendices: [tbl-1:1, tbl-2:2, app-1:1]   # 別表・別紙の並びと番号（id:番号）
---
```

別表・別紙の番号は外部から引用される（「規約別紙7」）ので、削除しても詰めません。`id:番号` で明示します。

## 4. 構造（記法）

| 要素 | ソース | 出力 |
|------|--------|------|
| 章 | `# {#ch-1} 総則` | 第1章　総則 |
| 節 | `# {#sec-5-1 section} 組合員`（章の中） | 第1節　組合員 |
| 条 | `## {#art-purpose} 目的` | 第1条（目的） |
| 項 | `1. {#art-purpose-p1} …`（番号付きリスト） | 第1項は番号なし、第2項以降は「2　…」 |
| 号 | 項の下にネスト | （１）　… |
| 号の細分 | さらにネスト | ア．　…、（ア）　… |
| 附則 | `# {#sup supplementary} 附則` | 附則。条は第1条から振り直す |
| 附則の「１．」形式の項 | `1. {#sup-art-002-p2 counted} …` | １．　… と通し番号 |

- `{#id}` が ID です。**一度付けたら変えません。** 項・号の ID は `art-xxx-pN`、`art-xxx-pN-iM` のように付けると読みやすくなります。
- 条の見出しに括弧は書きません。出力のときに「（目的）」と付けます。
- 号の本文に改行を入れると、「用語＋説明」の形（定義の条など）になります。

### 枝番と削除

```markdown
## {#art-minpaku branch} 住宅宿泊事業の禁止      → 直前の条の枝番（第5条の2）。以降の条番号は動かない
## {#art-duty} 区分所有者の責務 {deleted}          → 「第7条　削除」。番号の枠と ID を残す
1. {#art-x-p4 branch} …                          → 項の枝番（「４の２」）
   1. {#art-x-p1-i3 branch} …                    → 号の枝番（「（３）の２」）
```

条の追加は、枝番（番号を動かさない）か繰り下げ（以降の番号が1つずつ動く）かを、改正のたびに選べます。
繰り下げても、参照は ID なので自動で追随します。

## 5. 参照

本文中に `{ref:…}` で書きます。

| 書き方 | 出力の例 |
|--------|----------|
| `{ref:art-purpose}` | 第1条 |
| `{ref:art-repair-p1}` | 第8条第1項 |
| `{ref:art-def-p1-i2}` | 第2条第1項第２号 |
| `{ref:bylaw-parking#art-apply}` | 駐車場使用細則第2条（他の文書の条。文書の呼び名が付く） |
| `{ref:kiyaku#art-parking\|as=管理規約}` | 管理規約第12条（呼び名を上書き） |
| `{ref:art-x\|title}` | 第12条（駐車場の使用）（条名つき） |
| `{ref:art-a..art-b}` | 第16条から第18条まで |
| `{ref:art-x-p1\|rel}` | 直前なら「前項」「前条」、直後なら「次項」「次条」、それ以外は番号 |
| `{ref:art-x-p1\|local}` | 同じ条の中の項は「第1項」と、条番号を略す |
| `{ref:art-x\|self=本使用細則}` | 本使用細則第4条（自分の文書への参照に呼び名を付ける） |
| `{ref:tbl-1}` | 別表第1（別紙なら「別紙1」） |
| `{ext:区分所有法 第7条}` | 区分所有法 第7条（外部の法令。解決せずそのまま出す） |

- 参照先が存在しない、削除済みの条を指している、は整合性チェックでエラーになります。
- 同じ条の複数の項を並べるとき（`{ref:art-x-p2,art-x-p3}`）は、「第17条第2項および第3項」のようにまとめます。

## 6. 番号の計算

番号は出力のときに、文書内の並び順から計算します。

- 条番号: 本則の条を上から数える。`branch` の条は直前の条の枝番。`deleted` の条も番号を持つ。附則は別に数える。
- 項: 第1項は無印、第2項以降は「2」「3」。`branch` の項は直前の項の枝番（「4の2」）。`counted` の項は通し番号（「１．」）。
- 号: `（１）`、`（２）`…。`branch` の号は「（３）の２」。細分は「ア．」「（ア）」。
- 参照は、参照先の ID から、各版ごとに計算した番号を出す。

## 7. 版（改正）

`src/revisions.yaml` に並べます。

```yaml
revisions:
  - resolution: 2022-03-20      # 総会の決議日
    effective: 2022-04-01       # 施行日
    ref: v2022-04-01            # その版の条文を持つ git の参照（タグ）。空なら「記録のみ」
    note: 備考
    changes:
      - 管理規約 改正
```

- `ref` のある版は、その時点の `src/` を git から取り出して、条文を再現できます。
- `@2020-01-01` のように日付を指定すると、その日に有効な（`ref` を持つ）最新の版を使います。
- 改正の手順: `src/` を編集 → 整合性チェック → コミット → 施行日のタグを付ける → `revisions.yaml` に版を足す
  （GUI の「版の一覧」→「新しい版として登録…」で、タグの作成と `revisions.yaml` への追記までできます）。

## 8. 新旧対照表

条の ID で新旧を対応づけ、番号は各版で計算した値を出します。変更のない条は載せません。

| 区分 | 意味 |
|------|------|
| 新設 / 削除 | 条が増えた／消えた（削除は「第N条　削除」として残る） |
| 改正 | 本文・見出しが変わった。旧側は `~~削除~~`、新側は `**追加**` で示す（全角・半角の数字の違いは変更にしない） |
| 参照の自動更新 | 本文は同じで、参照している番号だけが変わった |
| 条番号のみ変更 | 条の位置が動いて番号だけが変わった |
| 別表・別紙 | 変更の有無だけを載せる（表の中身の差分は出さない） |

末尾に「要確認」として、ID に変換されていない直書きの参照（「前条」「第5条」など）を挙げます。
改正で番号が動くと意味が変わるため、改正の前に人が確かめてください。

## 9. 整合性チェック

| コード | 重大さ | 内容 |
|--------|--------|------|
| E-REF | エラー | 参照先の ID が存在しない（項・号の存在も確かめる） |
| E-DELETED | エラー | 削除済みの条への参照 |
| E-DUP-ID / E-DUP-DOC | エラー | ID・文書 ID の重複 |
| E-APPENDIX | エラー | 別表・別紙が親の `appendices` に載っていない／存在しない |
| W-BARE-NUM | 警告 | 本文に条番号が直書きされている |
| W-BARE-REL | 警告 | 「前条」「前項」「同条」などの相対参照が直書きされている |
| W-NOID | 警告 | 条に ID がない |

エラーがあると Word 出力はできません。

## 10. 出力

- **Markdown**: `python -m kiyakunote build src -o out`。番号・参照を展開した文書を、文書ごとに出す。
- **Word**: `python -m kiyakunote docx src -o out/docx`。規約・細則に別表・別紙・別図を付けて `.docx` にする。規約には巻末の改訂履歴と署名（`src/okugaki.txt`）も付く。
- **新旧対照表**: Markdown または Word（A4横の3列表。旧側の削除は赤の取消線、新側の追加は青の太字・下線）。
- **検索**: SQLite FTS5。日本語は trigram（3文字以上の部分一致）、1〜2文字は LIKE。全角・半角は NFKC で揃える。
  語を空白で並べると AND。条・項・号・別表のセルを1行ずつ索引する。

## 11. できないこと・範囲外

- 条の移動・分割（ID が同じなら同じ条として扱う）。
- 別表・別紙の表の中身の差分。表の結合・結合の解除（画面では、結合セルのある表のセル・行・列の編集、Excel との受け渡し、画像の差し替え、別表・別紙・別図の新設と削除ができる）。
- 既存の規約（Word・PDF）の自動取り込み（手作業。`kiyakunote.idify` が参照の ID 化を助ける）。
- 法的な判断。決議の要件（特別決議など）の確認は含まない。
